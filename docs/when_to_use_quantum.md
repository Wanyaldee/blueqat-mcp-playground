# 業務で使うなら、量子より枯れた技術のほうが優れているかもしれない

このドキュメントだけは他のdocsと毛色が違います。README や他のdocsは「気軽に量子コンピューティングに
触れてみる」ためのものですが、ここは実際の業務・プロダクトへの採用を検討する人向けに、あえて意地悪な
視点で書いています。

## 結論を先に

現時点(2026年)で、このリポジトリの規模感（free: 最大10量子ビット/256ショット、paid: 最大20量子ビット/
4000ショット、実機でも32量子ビット。詳細は[tiers_and_pricing.md](tiers_and_pricing.md)）の組合せ最適化・
シミュレーションを実際の業務判断に使うなら、ほぼ確実に**枯れた古典技術**（厳密解法・実績あるヒューリスティクス・
既存ソルバー）のほうが優れています。

このリポジトリの主目的は「量子コンピューティングの技術に気軽に触れて理解を深めること」であり、
「量子が実務で古典に勝る」ことを示すものではありません。

## 2つの軸を分けて考える

「量子は理論上こう優れている」と「実際に業務で採用してよいか」は別の質問です。

### 計算量的に量子が古典に勝つと言えるか

- **QAOA/VQE**（[applications.md](applications.md)の組合せ最適化・基底エネルギー探索）は
  NISQ時代のヒューリスティクスで、実用規模での優位性が証明された例はまだありません。実機のノイズは
  むしろ解の質を下げます。
- **Grover探索**は理論上 $\sqrt{N}$ 倍の高速化がありますが、これはフォールトトレラント量子コンピュータでの
  大規模実行が前提です。[例3](../examples/03_grover_search.md)のような小規模デモでは体感できません。
- **量子乱数生成（QRNG）**の「予測不可能な真の乱数」という性質自体は、量子コンピュータ特有のものでは
  ありません。枯れたハードウェア乱数生成器（TRNG、`/dev/hwrng`、HSM内蔵の乱数源など）でも同様に得られ、
  かつずっと安価で実績があります。blueqat MCPの差別化点は `run_id` による第三者検証性というサービス設計
  であって、量子力学そのものの優位性ではありません。

### 運用面で枯れた技術が勝ることが多い

- **コストの予測可能性**: 実機ジョブは稼働ウィンドウがあり常時オンではなく、キャンセル・返金不可の課金
  方式です（[hardware.md](hardware.md), [tiers_and_pricing.md](tiers_and_pricing.md)）。枯れた技術には
  この種の不確実性がありません。
- **信頼性・実績**: 量子ハードウェアはまだ研究・実証段階です。既存のソルバー・データベースには何十年もの
  実運用実績があります。
- **人材・エコシステム**: 量子アルゴリズムを書ける人材、デバッグツール、監視・運用のノウハウは、古典技術に
  比べてまだ圧倒的に薄いです。

## それでもこのリポジトリで遊ぶ価値

- QUBOへの落とし込み方、変分法（QAOA/VQE）の考え方など、量子アルゴリズムの「型」を手を動かして体感できる。
- 将来フォールトトレラント量子コンピュータが実用化されたときに、どの問題がどう解けそうかの土地勘を先に
  持っておける。
- MCP経由なのでSDKのインストールも実行環境構築も不要で、学習コストが低い。

## 実務導入を検討する際の簡易チェックリスト

1. 同じ問題を古典ソルバー（厳密解法、または実績あるヒューリスティクス）で解いた場合と、実際に比較したか。
2. コスト・レイテンシ・信頼性の予測可能性は、業務要件を満たすか。
3. 「量子でなければ実現できない性質」を本当に必要としているか、それとも枯れた技術で代替可能か
   （QRNGの例のように、代替可能なことが多い）。
4. 何のためにこの技術を採用するのか ── 学習・研究目的か、それとも実運用目的か。目的によって答えは変わる。
