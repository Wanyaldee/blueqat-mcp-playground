# ワークショップ進行ガイド: 「AIに頼むだけで量子コンピュータに届く」

生活・経営・研究の身近な悩みを、Claude や Codex などのAIエージェントに日本語で頼むだけで、
blueqat MCP 経由で量子コンピュータ（のシミュレータ）に解かせるところまで体験してもらうための進行ガイドです。

## 最初に: このワークショップの位置づけ

**このワークショップは「量子コンピューティングでこういうことができる」と知ってもらうためのものです。
「量子コンピュータのほうが速い・優れている」と主張するものではありません。**

ここで使う例はどれも、手作業や普通のプログラムで一瞬（1ミリ秒未満）で解ける小さな問題です。
量子を使わなければ解けない問題は1つもありません。それでもこの形にしているのは、次の3つを体験してほしいからです。

1. **入口の低さ**: 量子回路もPythonも書かずに、日本語で頼むだけで量子コンピュータに計算を投げられる
2. **定式化の考え方**: 「〇〇は避けたい」「ちょうど△個」といった現場のルールを罰点として書き、
   最小化問題にする。この考え方は量子でも古典でもそのまま使える
3. **結果を疑う習慣**: 量子の答えをそのまま信じず、古典的な方法の答えと比べる

## 量子が不要なケース（必ず伝えること）

参加者が「何でも量子で解けばいい」と持ち帰らないよう、次のことは明確に伝えてください。

- **今の規模なら古典で十分です。** 変数が数十個までなら全探索、それより大きくても整数計画ソルバー
  （OR-Tools、Gurobi など）や焼きなまし法で実用的に解けることが多いです。free tier の上限（10量子ビット・QUBO 20項）は、
  古典なら一瞬で解ける規模です。
- **素朴な方法で十分なことも多いです。** [例19](../examples/19_reviewer_assignment.md)のように、
  「良い順に取る」だけで最適解が出る問題もあります。まず素朴な方法と比べ、差がなければ最適化は不要です。
- **QAOAは必ず最適解を返すわけではありません。** [例15](../examples/15_weekend_shift.md)では1回目の実行で
  最適解を外しました。確率的に良い答えを探すヒューリスティックであり、古典の厳密解法より信頼性は低いです。
- **実務では「枯れた技術」のほうが優れていることが多いです。** コストの予測しやすさ、実機の稼働時間の制約が
  ないこと、ノイズがないこと、扱える人材がいること。こうした運用面では、古典の実績ある手法が勝ちます。
  詳しくは [when_to_use_quantum.md](when_to_use_quantum.md) を参照してください。
- **一番難しいのはソルバー選びではなく、数値化です。** 相性・見込み売上・情報量といった数字をどう決めるかのほうが、
  結果を大きく左右します。

「では量子は何の役に立つのか」と聞かれたら、 **大規模・高難度の問題で古典を超える可能性が研究されている段階で、
今は手法を学び・試す時期** と答えるのが誠実です（[applications.md](applications.md) の「誠実に書いておくべきこと」も参照）。

## 事前準備

### 主催者側

1. blueqat MCP の API キーを取得する（[mcp.blueqat.app](https://mcp.blueqat.app)）
2. Claude Code に登録する。キーはコマンドに直接書かず、環境変数から渡すのがおすすめです。

   ```
   claude mcp add --transport http blueqat https://mcp.blueqat.app/mcp \
     --header "Authorization: Bearer $BLUEQAT_API_KEY"
   ```

   Codex など他のMCPクライアントを使う場合は、そのクライアントのMCP設定方法に従ってください。
3. `/mcp` で `blueqat` が Connected になっていること、`account_status` が返ってくることを確認する
4. 当日のデモを一度通しでリハーサルする（free tierでは10秒のタイムアウトがあるため、規模を大きくしすぎない）

### 参加者が手を動かす場合

- 参加者ごとに API キーが必要です。free tier の制限（10量子ビット・256ショット・QUBO 20項・10秒）は
  `sdk_info` ツールで確認できます。
- **API キーをチャットやスライドに貼らないよう**に案内してください。会話ログに残ります。

## 当日の注意点

- **結果は実行ごとに変わります。** QAOAは確率的なので、ライブデモの出現回数や、最適解が出るかどうかは
  ページに載せた結果と異なることがあります。外れたら「これがヒューリスティックということです」と説明する
  教材にしてください。
- **free tier の10秒制限に注意してください。** `n_starts` を増やしたり問題を大きくしたりするとタイムアウトします
  （[例7](../examples/07_qaoa_budget_matching.md)、[例15](../examples/15_weekend_shift.md)で実際に発生）。
- **ネットワークが不安定な会場では**、事前に実行した結果（各ページの `run_id`）を見せる形に切り替えられます。
  `run_id` のリンクから、その計算が実際にサーバー上で実行されたことを誰でも確認できます。
- 実機QPUへのジョブ投入（`submit_hardware_job`）は有料・取り消し不可です。ワークショップではシミュレータだけを
  使い、実機は扱わないことをおすすめします。

## 想定される質問

**Q. 量子コンピュータのほうが速いのですか？**
A. 今日の規模では速くありません。古典の全探索のほうが速く、確実です。今日はAIを通して量子に届く手軽さと、
問題を最適化の形に書く考え方を体験してもらうのが目的です。

**Q. では、いつ量子が役に立つのですか？**
A. 古典では手に負えない大規模な問題で優位性が出る可能性が研究されていますが、組合せ最適化で実用的な優位性は
まだ示されていません。分子シミュレーション（[例12](../examples/12_vqe_h2_molecule.md)）のように、
量子系そのものを扱う分野が有望とされています。

**Q. 自分の仕事のシフト作成に使えますか？**
A. 今の実務規模なら、制約ソルバーや市販のシフト管理サービスのほうが現実的です。ただ、今日の「ルールを
罰点で書く」考え方は、それらのツールを使うときにもそのまま役立ちます。

**Q. AIが作ったQUBOが正しいか、どう確かめればいいですか？**
A. 小さな規模で全探索の答えと比べるのが一番確実です。このリポジトリの
[scripts/build_workshop_qubos.py](../scripts/build_workshop_qubos.py) は、例14〜19のQUBOを全探索で
答え合わせするスクリプトです。
