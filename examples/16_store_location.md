# 例16: 出店候補地の選定 — 「売れそうな順」に選ぶと共食いする

> **ワークショップ向けの応用例です。** この規模なら手作業や普通のプログラムでも一瞬で解けます。
> 結果はシミュレータ（ノイズのない理想的な量子コンピュータ）のもので、実機では同じようにはいきません
> （[docs/simulator_vs_hardware.md](../docs/simulator_vs_hardware.md)）。
> ここで見せたいのは「量子のほうが速い」ことではなく、**「単体で良いものを順に選ぶ」直感が、組み合わせの
> 相互作用で外れることがある、というのを最適化問題として表せること**です。量子が不要なケースについては
> [docs/workshop.md](../docs/workshop.md) と [docs/when_to_use_quantum.md](../docs/when_to_use_quantum.md) を参照してください。

## 悩み

新しく2店舗を出したい。候補地は5つあり、それぞれ単独で出したときの見込み月商は分かっている。
ただし、近い候補地に両方出すと、お互いに客を奪い合う（カニバリゼーション）。

| 候補地 | 単独の見込み月商（百万円） |
|---|---|
| 駅前 | 10 |
| 大学前 | 7 |
| 住宅街 | 6 |
| 国道沿い | 8 |
| 商店街 | 5 |

| 両方に出すと | 合計が減る額（百万円） |
|---|---|
| 駅前 × 大学前 | −4 |
| 駅前 × 商店街 | −5 |
| 駅前 × 国道沿い | −3 |
| 大学前 × 商店街 | −2 |
| 住宅街 × 国道沿い | −1 |

数値はワークショップ用の架空のものです。

## Claudeへの頼み方

```
blueqat MCPで出店候補地を2つ選びたいです。
単独の見込み月商: 駅前10, 大学前7, 住宅街6, 国道沿い8, 商店街5（百万円）
両方出すと減る額: 駅前×大学前 4, 駅前×商店街 5, 駅前×国道沿い 3, 大学前×商店街 2, 住宅街×国道沿い 1
合計が最大になる2つをQAOAで探して、「月商の大きい順に2つ」と比べてください。
```

## 定式化（何を「罰点」にしたか）

「その候補地に出店するなら1」という変数を5個（5量子ビット）用意し、次を最小化します。

| 項 | 意味 |
|---|---|
| 売上の項 | 出店した候補地の見込み月商の合計（マイナスにして、大きいほど値が下がるようにする） |
| 共食いの項 | 両方に出店した組み合わせについて、減る額を足す |
| 「ちょうど2店」の罰点 | 出店数が2からずれた分の2乗 × 30 |

QUBOの項は15個です。生成スクリプトは [scripts/build_workshop_qubos.py](../scripts/build_workshop_qubos.py) です。

## 結果

| 選び方 | 選んだ2店 | 合計の見込み月商 |
|---|---|---|
| 月商の大きい順に2つ（直感） | 駅前 + 国道沿い | 10 + 8 − 3 = **15** |
| QAOAの最良（`10100`、256回中9回） | 駅前 + 住宅街 | 10 + 6 = **16** |
| 全探索の最適解 | 駅前 + 住宅街 | **16** |

単独では3番目の「国道沿い」より弱い「住宅街」を選ぶほうが、駅前との共食いがないぶん合計では上回ります。
QAOAは全探索と同じ最適解を見つけました。

`proof`: [✓ 実行済み sim_20261004_04027c3773d05e6b](https://mcp.blueqat.app/runs/sim_20261004_04027c3773d05e6b)

正直に書いておくと、差は月100万円（15 → 16）で、見込み月商の誤差のほうが大きいかもしれません。
ここで伝えたいのは金額の大小ではなく、**「単体で良い順」と「組み合わせて最良」は別物**だという点です。

## 古典的な方法との比較

- 全探索: 2^5 = 32通り（2店の組み合わせだけなら10通り）。手元のPythonで**1ミリ秒未満**で厳密解が出ます。
- 10通りなら、Excelで表を作っても十分です。

この規模で量子を使う理由は**ありません**。直感（貪欲法）が外れることを示すのに、量子は必要ありません。
必要なのは「相互作用まで含めて全体を評価する」という考え方です。

## 実務で使うなら

- 本当に難しいのは、見込み月商や共食いの度合いを推定する部分（商圏分析・人流データ・競合調査）です。
  ソルバーの選択より、この推定の精度が結果を左右します。
- 候補地が数百・出店数が数十になる規模では、施設配置問題として整数計画ソルバー（Gurobi、OR-Tools
  など）を使うのが一般的です。
